# Fury of the Sky — правила проекта

Аркадный воздушный бой для PSP (homebrew). Целевое железо — **реальная PSP-3006 с CFW**,
эмулятор используется только для внутренних smoke-тестов. Сейчас в работе современная эпоха
(Су-35С); эпохи «Вторая мировая» и «будущее», сюжет и мультиплеер — позже, без запроса не трогать.

## Документация — обязательное правило

По разработке под PSP почти нет актуальной информации, архитектура будет сложной, поэтому
репозиторий — это и есть база знаний. **Задача не считается выполненной, пока не обновлена
документация.** Документация меняется в том же изменении, что и код.

| Что произошло | Куда писать |
|---|---|
| Принято техническое/архитектурное решение (формат, библиотека, подход, компромисс) | новый ADR `docs/decisions/NNNN-краткое-имя.md` по шаблону `docs/decisions/0000-template.md` |
| Решение пересмотрено | новый ADR; в старом статус «Заменён NNNN» (старые ADR не переписываем) |
| Обнаружено поведение PSP / GE / прошивки / тулчейна / эмулятора, особенно найденное отладкой | `docs/psp/*.md`: симптом → причина → решение → **где проверено** (железо / эмулятор / не проверено) |
| Изменён или добавлен формат файла | `docs/formats/*.md`; при несовместимом изменении — новая версия magic (`FSM3` → `FSM4`) |
| Изменилась структура кода, поток кадра, память, конвейер ассетов | `docs/architecture.md` |
| Новый самолёт / ассет | `docs/assets/<имя>.md`: референсы, размеры, бюджет полигонов, ливреи, открытые вопросы |
| Рабочая сессия | запись в `docs/devlog.md`: дата, что сделано, что сломалось и почему, что дальше |
| Изменились планы | `docs/roadmap.md` |

Правила текста:
- Пишем по-русски, идентификаторы и API — как в коде.
- Факты о железе помечаем, где они проверены. Непроверенное так и называем — «не проверено».
- Указываем точные значения: адреса, размеры, коды ошибок, NID. Это то, чего нет в интернете.
- Комментарии в коде — по-английски, кратко, объясняют *почему*.

## Сборка и проверка

```bash
tools/install_toolchain.sh                 # один раз: pspdev в ~/pspdev + сборка
psp-cmake -B build/psp && cmake --build build/psp
cmake -B build/host && cmake --build build/host && ctest --test-dir build/host   # тесты физики на Mac
tools/smoke_test.sh                        # прогон в PPSSPP (software renderer) + скриншоты
python3 tools/textures/env.py              # текстуры окружения
python3 tools/textures/fx.py               # текстуры эффектов и HUD
tools/deploy.sh                            # копирование на PSP в режиме USB
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
    --python tools/models/build.py -- su35s   # пересборка модели, превью в build/previews/
```

Перед тем как отдавать сборку на железо: host-тесты и `tools/smoke_test.sh` должны пройти
(нет `Unknown syscall`, скриншоты осмысленные). Подробности — `docs/workflow.md`.

`src/game`, `src/fx` и `src/math` — платформенно-нейтральные: **никаких заголовков PSP** (их собирают host-тесты).

## Известные ловушки (полный список — docs/psp/gotchas.md)

- **Не линковать `pspkernel`** — подтягивает заглушки `*ForKernel`, на железе чёрный экран.
- Данные для GE (меши, текстуры, CLUT) после записи CPU — `sceKernelDcacheWritebackRange`.
- Скриншоты/чтение VRAM в PPSSPP корректны только с software renderer.
- Отсечение граней `GU_CCW`; 2D-полосы и купол неба рисовать без отсечения.
- **Матрицы GE 24-битные** → мировые координаты в матрицы не передавать: только `gfx::setCamera` +
  `gfx::setModel*` (рендер относительно камеры, ADR 0013). Вершины, которые пишет CPU, — относительно `renderOrigin()`.
- В HUD справа сверху — id сборки (`<hash>[+] HH:MM`): по фото с PSP видно, какая версия запущена.
- 2D (`GU_TRANSFORM_2D`): UV в **текселях**. Аддитивные проходы — с чёрным цветом тумана (`setAdditiveFog`).
- Ближняя плоскость не меньше 3 м, у камеры — только мелкие треугольники (иначе GE их отбрасывает, №19).
- Готовый кадр читать только в `overlay` (после `sceGuSync`): GE рисует, пока CPU пишет список (№23).
- Меш — FSM4 с подвижными частями; новый руль = `joint()` + `lifting_surface(movers=…)` (ADR 0015).
