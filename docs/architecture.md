# Архитектура

Состояние: **M2 «Бой» и M2.5 «Меню»**: игра стартует в меню над живым 3D-ангаром (кампания из 4 локаций по
4 миссии, тренировка, ангар с магазином, профиль, настройки, мультиплеер-заглушка). Вылет — полёт со
сверхманевренностью, подвижными рулями, эффектами, HUD и звуком, оружием (Р-73, Р-77, ГШ-30-1), РЛС, СПО и
противником с ИИ; миссия — уничтожить N противников подряд.
Документ описывает то, что есть в коде сейчас; планы — в [roadmap.md](roadmap.md).

## Слои и зависимости

```
main ──► scenes ──► audio ──► fx ──► game ──► math   (meta, audio, fx, game, math — и на Mac)
            │
            ├──► meta ──► game                (контент, профиль, SortieConfig/Result)
            ├──► ui ──► render ──► core       (render знает fx/game только как данные для отрисовки)
            └──► platform ──► audio, meta     (аудиопоток тянет audio::mixer(); psp_save пишет профиль)
```

- Экраны меню (`menu::Screen`, ADR 0035):
  - `enter()` вызывается и при `push`, и когда экран снова оказался сверху после `pop` — в том числе после
    закрытия диалога «да/нет». Экран, которому нужен «первый вход», держит свой флаг.
  - `update()` получает ввод, только когда экран сверху и переход почти закончился; `draw()` — каждый кадр,
    анимации двигаются в нём по `ctx.dt`.
  - Диалог `ctx.confirm(вопрос, onYes, "BUY")` сам играет `Sfx::Confirm` на «да». Вопрос хранится указателем —
    строка должна жить, пока диалог открыт.
  - Статичные экраны рисуют `ui::bottomBar` первым, чтобы их плиты лежали поверх тени плашки; прокручиваемые
    списки — наоборот, чтобы уходить под неё.
- `meta` — как `game`: таблицы контента и правила прогресса, проверяются host-тестами `meta`.
  Меню отдаёт полёту `meta::SortieConfig`, полёт возвращает `meta::SortieResult`; больше сцены друг о друге
  ничего не знают.
- `game`, `fx` и `math` **не включают ни одного заголовка PSP** — это граница, по которой проходят host-тесты и
  будущий сетевой код. Состояние симуляции (`FlightState`) — простые данные, отдельно от отрисовки.
- `fx` — визуальная симуляция (частицы, ленты, события вроде хлопка). Детерминирована, но в сетевую синхронизацию
  не входит: каждый клиент считает её сам из `FlightState`. Ловушки — в `game`: на них будут реагировать ракеты.
- `render` ничего не знает об игровой логике; сцены связывают `game` с `render`.
- `scenes::Scene` — интерфейс экрана (`enter / leave / update / render / overlay`), виртуальные функции без RTTI.
- `audio` — как `fx`: решает, *что* должно звучать (уровни петель, какая фраза), из `FlightState`; детерминирован.
  Платформенная часть — только поток вывода в `platform/psp_audio`.

## Потоки

| Поток | Приоритет | Назначение |
|---|---|---|
| `user_main` | 0x20 | всё: ввод, симуляция, построение списка команд GE |
| `callbacks` | 0x11 | спит в `sceKernelSleepThreadCB`, принимает exit callback от HOME |
| `audio` | 0x12 | разбирает очередь команд микшера, смешивает блок 1024 кадра, `sceAudioOutputPannedBlocking` (ADR 0024) |

Игровой поток и аудиопоток делят только кольцо команд `audio::Mixer` (SPSC, без блокировок). Игра пишет
`play / set / stop / setWorldGain`, аудиопоток применяет их в начале блока.

## Кадр

```
readPad                      ввод (мёртвая зона стика 22%)
сцена — MenuScene или FlightScene:
  MenuScene.update           экран сверху стека (Context: профиль, навигация, звуки, launch), камера ангара
                             переезжает к пресету экрана; launch(SortieConfig) → FlightScene.configure + enter
  FlightScene: finished()    → result() → MenuScene.sortieReturned: статистика, награда, медаль, звание,
                             сохранение profile.dat, дебрифинг (миссия) или возврат на экран тренировки
START → пауза (в полёте)     металлическое меню паузы: продолжить / рестарт / выйти (abort), «мир» заглушён
scene.update(pad, dt)        FlightScene: аккумулятор, шаги по 1/60 с (≤ 5 за кадр). Шаг:
                               FlightModel.step → ControlSurfaces → Countermeasures
                               → Bot (пилот → автопилот → своя FlightModel; своя РЛС и Armament по нам)
                               → TargetList → Radar.update → Armament.update (кнопки, головка Р-73, пуски,
                                 ракеты, пушка, перезарядка, кусок расчёта ЗРП) → попадания в бота / в нас,
                                 HIT/MISS/DESTROYED/SHOT DOWN → Rwr.update
                               → ChaseCamera → AircraftEffects ×2 (игрок, цель) → WeaponEffects ×2 (наше, его)
                               → FlightAudio, щелчки ловушек, поджиг, взрыв, звуки оружия (подрывы с задержкой
                                 расстояние/340 м/с), тон ГСН, тоны СПО, VoiceInformer → фраза
                             затем раз за кадр: уровни 5 петель → mixer.set (FlightScene::updateAudio)
beginFrame                   clear: в полёте — цвет дымки, в меню — тёмный
scene.render()               FlightScene (порядок важен, см. ниже) или MenuScene: ангар (запечённый свет, без
                             освещения GE) → тень на полу → самолёт на шасси со светом «ворота + лампы» и подвеской
                             → begin2D → затемнение → уходящий и входящий экраны со сдвигом/прозрачностью → end2D
[пауза] drawPause            меню паузы UI-китом поверх кадра
sceGuFinish (kickFrame)      список отдан; GE рисует его, пока CPU уже считает следующий кадр (ADR 0049):
следующая итерация:          readPad → scene.update (кадр N+1) → sceGuSync (waitFrame, ждём кадр N) →
                             overlay (FPS, id сборки, чтение пикселей для блика, скриншот) → vsync → swap →
                             beginFrame/render (список N+1) → kickFrame
```

Порядок `FlightScene::render`:
1. Проекция (near 3 м, far 12 км), камера = начало координат рендера.
2. Небо и солнце (без глубины), туман, море (две сетки + проход волн), солнечная дорожка.
2а. Скалы и острова: куски по ошибке ≤ 10 px, от ближних к дальним, без освещения GE. Свет «солнце + небо + море»
   запечён в цвет вершин FTR2 на каждое размещение при смене погоды (`FlightScene::bakeRocks`, ADR 0051). Куски у
   глаза — программное отсечение. Затем прибой у подножий (только куски береговой линии в кадре), корабли и их эффекты.
3. Тень и самолёт по частям (свет: солнце + небо + море + точечный свет форсажа), ракеты на пилонах; тестовая цель
   (другая ливрея) — только в конусе камеры и ближе 5 км, дальше 120 м LOD-копией с одним источником света
   (ADR 0032); ракеты в полёте — с тем же отсечением.
4. Облака (отсортированы).
5. Эффекты: ленты (следы, ловушки, дым ракет, дым цели) → частицы (самолёт, цель, оружие) → конденсат →
   трансзвуковое облако (клубы, ADR 0020/0023) → пламя → ловушки → факелы ракет → трассеры → дульное пламя →
   штрихи скорости.
6. 2D: блик линзы, белая заливка внутри облака, HUD v3 (ADR 0049; прицеливание — ADR 0028, захват — ADR 0050):
   `drawFlightHud` копит всё в холст, `flush(line, hudFont, hudPlates)` рисует подложки → штрихи → плашки
   тревог → растровый текст. Лестница уступает место тревогам, сообщению и блоку цели и не заходит на самолёт.

Пламя и тень зависят от отклонения сопел: `Mesh::partTransform` даёт мировую систему сопла.

**Рендер относительно камеры** (ADR 0013): `setCamera` делает глаз началом координат, `setModel*`
вычитают его из мировых позиций на CPU — в 24-битные матрицы GE попадают только малые числа. Вся геометрия
эффектов и точечный свет считаются на CPU относительно `renderOrigin()`.

GE начинает выполнять список, пока CPU его дописывает ([gotchas №23](psp/gotchas.md)); читать готовый кадр можно
только в `overlay`. CPU ждёт GE в конце кадра. Частота CPU — 333/166 МГц (`platform::setMaxClock`); если не
удалось — в углу красное «222!».

## Память

### VRAM (2 МБ)
| Диапазон | Размер | Содержимое |
|---|---|---|
| `0x000000–0x087FFF` | 544 КБ | кадровый буфер 0, 512×272, 8888 |
| `0x088000–0x10FFFF` | 544 КБ | кадровый буфер 1 |
| `0x110000–0x153FFF` | 272 КБ | глубина 16 бит |
| `0x154000–0x1DBFFF` | 544 КБ | кадровый буфер 2 — тройная буферизация (ADR 0049) |
| `0x1DC000–0x1FFFFF` | 144 КБ | свободно |

### Основная память
- Куча: `PSP_HEAP_SIZE_KB(-1024)` + `MEMSIZE=1`.
- Список команд GE: статический 1 МБ. Покадровая геометрия через `sceGuGetMemory`: в худшем случае ~300 КБ
  (HUD ~100 КБ, ленты ~55 КБ, пламя ~45 КБ, облака ~18 КБ, частицы ~15 КБ).
- Ассеты (`scenes::Assets`, грузятся при старте): меш Су-35С 233 КБ (FSM4, 11 частей), 2 ливреи по 341 КБ,
  океан 86 КБ, облако/солнце по 6 КБ, текстуры эффектов ~70 КБ.
- Статическая геометрия мира в объектах сцен (сцены — `static` в `main`, не на стеке):
  небо ~6 КБ, океан ~45 КБ (две сетки), облака ~16 КБ. После заполнения — writeback кэша.
- Эффекты (`fx::AircraftEffects`): частицы 320 × ~60 Б, ленты 28 × 40 точек — ~45 КБ; таких два (игрок и
  цель). `fx::WeaponEffects`: частицы 320 + 17 лент — ~35 КБ. Оружие (`game::Armament`: 12 ракет, 96 снарядов,
  копия ракеты для ЗРП) ~5 КБ. Бот — ещё одна модель полёта, РЛС, `Armament` и `WeaponEffects` (~45 КБ).
  Всё в объекте сцены.
- HUD-холст: 1400 штрихов + 64 строки текста + 8 плашек, ~36 КБ, статический.
- Интерфейс (`ui::Resources`, грузится при старте): шрифт 257 КБ + метрики 15 КБ, шрифт HUD 65 КБ + 5 КБ,
  плашки тревог HUD 65 КБ (ADR 0049), скин 129 КБ, иконки 65 КБ,
  картинки локаций по 33 КБ, схемы техники 65 КБ. Меню (`MenuScene`) — меши ангара и шасси со своими текстурами
  (docs/assets/hangar.md) и 5 звуков `ui_*` (~36 КБ). 2D-кадр меню — 40–80 вызовов спрайтов, ~10–20 КБ в списке GE.
- Рельеф (`Assets::rocks`, грузится при старте): 15 мешей FTR2 ~8,5 МБ (5 больших массивов по 1,0–1,5 МБ;
  24 Б на вершину: 16 для GE + 8 для запекания, ADR 0051), 8 текстур (кожи кекуров + 2 тайла деталей).
  Копии вершин под повторные размещения формы (свет запечён под рыск каждой) — ~3,3 МБ, выделяются при первом
  запекании (`TerrainMesh::bake`, старт вылета) и живут всю сессию. Таблицы столкновений `rock_shapes.cpp`
  ~1,5 МБ в образе программы. Программное отсечение: буфер кодов 8 КБ + 1536 вершин по 24 Б (36 КБ), статические.
- Профиль игрока: 272 байта (`profile.dat`, docs/formats/profile.md).
- Меши и текстуры ракет — см. [assets/r73.md](assets/r73.md), [assets/r77.md](assets/r77.md).
- Звук: 23 WAV ~1,5 МБ в `Assets` (блобы живут всю сессию, микшер читает сэмплы прямо из них); микшер ~9 КБ
  (аккумулятор 1024×2×4 Б + кольцо 64 команд); два выходных буфера по 4 КБ; стек аудиопотока 16 КБ.

## Управление в меню

| Ввод | Действие |
|---|---|
| ↑ / ↓ | курсор |
| ← / → | значение, карусель, страница вкладок «ящика» (→ открывает, ← закрывает) |
| ✕ | выбрать / подтвердить |
| ○ | назад |
| L / R | страницы (брифинг), зум (ангар) |
| △ | доп. действие (ливрея в ангаре, повторный поиск лобби) |
| стик | вращение камеры в ангаре |
| START | запуск вылета из брифинга |

## Управление (FlightScene)

Раскладка Ace Combat X (ADR 0030):

| Ввод | Действие |
|---|---|
| Стик | на себя/от себя — угол атаки (нос вверх; инверсия в меню), влево/вправо — крен |
| R держать | полная тяга → форсаж |
| L держать | малый газ + тормоз (рули направления «разводятся») |
| L + стик до упора на себя | **ПСМ**: ограничители СДУ сняты, стик управляет носом (ниже 650 км/ч); выше — ограничитель 13g |
| ← / → | рыскание (скольжение; в ПСМ — разворот носа соплами) |
| ✕ держать | пушка ГШ-30-1 |
| ○ | пуск ракеты (одна на нажатие, крылья по очереди) |
| △ | следующая цель |
| SELECT | ракета Р-73 ↔ Р-77 |
| □ держать | залпы тепловых ловушек |
| ↑ | скриншот |
| START | пауза: продолжить, рестарт, выход в меню (в миссии — «прервать», вылет засчитывается без награды) |

Звук слышен сразу: двигатель (рёв, свист, форсаж с треском), обдув по скорости, тряска на больших α / G,
щелчки ловушек, пушка, пуски, далёкие подрывы, тоны головки, речевой информатор — реальные записи РИ-65:
«высота опасная», «предельная перегрузка», «предельный угол атаки», «скорость предельная», «пуск разрешён»
(ADR 0024, 0025, 0026).

«Кобра»: L + стик на себя до упора на ~1 с, отпустить. «Кульбит»: то же, стик держать до полного оборота.

## Системы координат
[ADR 0007](decisions/0007-coordinates-units.md): игра — X вправо, Y вверх, −Z вперёд, метры.
Связанные оси самолёта: угловые скорости `x` — тангаж (нос вверх), `y` — рыскание (нос влево), `z` — крен влево.
Угол атаки `α` — нос над траекторией, скольжение `β` — нос левее траектории.
Матрицы pspgum — по столбцам: `x/y/z` — образы осей, `w` — перенос (`gfx::setModel`).
Пространство рендера = мир − позиция камеры (ADR 0013).
