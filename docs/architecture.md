# Архитектура

Состояние: **M1.5 «Ощущения»**: тестовая сцена полёта со сверхманевренностью, подвижными рулями, эффектами,
HUD и звуком (двигатель, обдув, речевой информатор), плюс «Ангар».
Документ описывает то, что есть в коде сейчас; планы — в [roadmap.md](roadmap.md).

## Слои и зависимости

```
main ──► scenes ──► audio ──► fx ──► game ──► math   (audio, fx, game, math компилируются и на Mac)
            │
            ├──► render ──► core          (render знает fx/game только как данные для отрисовки)
            └──► platform ──► audio (аудиопоток тянет audio::mixer())
```

- `game`, `fx` и `math` **не включают ни одного заголовка PSP** — это граница, по которой проходят host-тесты и
  будущий сетевой код. Состояние симуляции (`FlightState`) — простые данные, отдельно от отрисовки.
- `fx` — визуальная симуляция (частицы, ленты, события вроде хлопка). Детерминирована, но в сетевую синхронизацию
  не входит: каждый клиент считает её сам из `FlightState`. Ловушки — в `game`: на них будут реагировать ракеты.
- `render` ничего не знает об игровой логике; сцены связывают `game` с `render`.
- `scenes::Scene` — интерфейс экрана (`enter / leave / update / render / overlay`), виртуальные функции без RTTI.
- `audio` — как `fx`: решает, *что* должно звучать (уровни петель, какая фраза), из `FlightState`; детерминирован.
  Платформенная часть — только поток вывода в `platform/psp_audio`.

## Потоки

| Поток | Приоритет | Назначение |
|---|---|---|
| `user_main` | 0x20 | всё: ввод, симуляция, построение списка команд GE |
| `callbacks` | 0x11 | спит в `sceKernelSleepThreadCB`, принимает exit callback от HOME |
| `audio` | 0x12 | разбирает очередь команд микшера, смешивает блок 1024 кадра, `sceAudioOutputPannedBlocking` (ADR 0024) |

Игровой поток и аудиопоток делят только кольцо команд `audio::Mixer` (SPSC, без блокировок). Игра пишет
`play / set / stop / setWorldGain`, аудиопоток применяет их в начале блока.

## Кадр

```
readPad                      ввод (мёртвая зона стика 22%)
START → пауза / меню         в паузе обновляется меню, сцена стоит, «мир» в микшере заглушён
scene.update(pad, dt)        FlightScene: аккумулятор, шаги по 1/60 с (≤ 5 за кадр). Шаг:
                               FlightModel.step → ControlSurfaces → Countermeasures → ChaseCamera
                               → AircraftEffects (+ событие 1 Маха — только для скриптов)
                               → FlightAudio, щелчки ловушек, поджиг, взрыв, VoiceInformer → фраза
                             затем раз за кадр: уровни 5 петель → mixer.set (FlightScene::updateAudio)
beginFrame                   clear цветом дымки + глубина
scene.render()               FlightScene (порядок важен, см. ниже)
[пауза] drawMenu             меню на HUD-холсте поверх кадра
endFrame                     sceGuFinish → sceGuSync → overlay (FPS, id сборки, чтение пикселей
                             для блика, скриншот) → vsync → swap
```

Порядок `FlightScene::render`:
1. Проекция (near 3 м, far 12 км), камера = начало координат рендера.
2. Небо и солнце (без глубины), туман, море (две сетки + проход волн), солнечная дорожка.
3. Тень самолёта на воде; самолёт по частям (свет: солнце + небо + море + точечный свет форсажа).
4. Облака (отсортированы).
5. Эффекты: ленты → частицы → конденсат → трансзвуковое облако (клубы, ADR 0020/0023) → пламя → ловушки → штрихи скорости.
6. 2D: блик линзы, белая заливка внутри облака, HUD (раскладка — ADR 0021).

Пламя и тень зависят от отклонения сопел: `Mesh::partTransform` даёт мировую систему сопла.

**Рендер относительно камеры** (ADR 0013): `setCamera` делает глаз началом координат, `setModel*`
вычитают его из мировых позиций на CPU — в 24-битные матрицы GE попадают только малые числа. Вся геометрия
эффектов и точечный свет считаются на CPU относительно `renderOrigin()`.

GE начинает выполнять список, пока CPU его дописывает ([gotchas №23](psp/gotchas.md)); читать готовый кадр можно
только в `overlay`. CPU ждёт GE в конце кадра. Частота CPU — 333/166 МГц (`platform::setMaxClock`); если не
удалось — в углу красное «222!».

## Память

### VRAM (2 МБ)
| Диапазон | Размер | Содержимое |
|---|---|---|
| `0x000000–0x087FFF` | 544 КБ | кадровый буфер 0, 512×272, 8888 |
| `0x088000–0x10FFFF` | 544 КБ | кадровый буфер 1 |
| `0x110000–0x153FFF` | 272 КБ | глубина 16 бит |
| `0x154000–0x1FFFFF` | 688 КБ | свободно |

### Основная память
- Куча: `PSP_HEAP_SIZE_KB(-1024)` + `MEMSIZE=1`.
- Список команд GE: статический 1 МБ. Покадровая геометрия через `sceGuGetMemory`: в худшем случае ~300 КБ
  (HUD ~100 КБ, ленты ~55 КБ, пламя ~45 КБ, облака ~18 КБ, частицы ~15 КБ).
- Ассеты (`scenes::Assets`, грузятся при старте): меш Су-35С 233 КБ (FSM4, 11 частей), 2 ливреи по 341 КБ,
  океан 86 КБ, облако/солнце по 6 КБ, текстуры эффектов ~70 КБ.
- Статическая геометрия мира в объектах сцен (сцены — `static` в `main`, не на стеке):
  небо ~6 КБ, океан ~45 КБ (две сетки), облака ~16 КБ. После заполнения — writeback кэша.
- Эффекты (`fx::AircraftEffects`): частицы 320 × ~60 Б, ленты 28 × 40 точек — ~45 КБ в объекте сцены.
- HUD-холст: 1100 штрихов, ~26 КБ, статический.
- Звук: 15 WAV ~1 МБ в `Assets` (блобы живут всю сессию, микшер читает сэмплы прямо из них); микшер ~9 КБ
  (аккумулятор 1024×2×4 Б + кольцо 64 команд); два выходных буфера по 4 КБ; стек аудиопотока 16 КБ.

## Управление (FlightScene)

| Ввод | Действие |
|---|---|
| Стик | на себя/от себя — угол атаки (нос вверх; инверсия в меню), влево/вправо — крен |
| L / R | рыскание (скольжение; в ПСМ — разворот носа соплами) |
| △ держать | полная тяга → форсаж |
| ✕ держать | малый газ + тормоз (рули направления «разводятся») |
| ○ держать | **ПСМ**: ограничители СДУ сняты, стик управляет носом напрямую (ниже 650 км/ч); выше — ограничитель 13g |
| □ держать | залпы тепловых ловушек |
| START | пауза: сцена, ливрея, инверсия тангажа, рестарт |
| SELECT | скриншот |

Звук слышен сразу: двигатель (рёв, свист, форсаж с треском), обдув по скорости, тряска на больших α / G,
щелчки ловушек, речевой информатор — реальные записи РИ-65: «высота опасная», «предельная перегрузка»,
«предельный угол атаки», «скорость предельная» (ADR 0024, 0025).

«Кобра»: ○ + стик на себя до упора на ~1 с, отпустить. «Кульбит»: то же, стик держать до полного оборота.

## Системы координат
[ADR 0007](decisions/0007-coordinates-units.md): игра — X вправо, Y вверх, −Z вперёд, метры.
Связанные оси самолёта: угловые скорости `x` — тангаж (нос вверх), `y` — рыскание (нос влево), `z` — крен влево.
Угол атаки `α` — нос над траекторией, скольжение `β` — нос левее траектории.
Матрицы pspgum — по столбцам: `x/y/z` — образы осей, `w` — перенос (`gfx::setModel`).
Пространство рендера = мир − позиция камеры (ADR 0013).
