# 0015 — Подвижные части самолёта: формат FSM4 и аниматор рулей

- **Статус:** Принято (заменяет [0006](0006-mesh-format-fsm3.md) в части формата: FSM3 → FSM4)
- **Дата:** 2026-10-14

## Контекст
Отзыв автора: «у моделей самолётов должны быть подвижные элементы, сейчас это по факту просто крутящаяся
модель». У Су-35С подвижны стабилизаторы (цельноповоротные), флапероны, отклоняемые носки крыла, рули
направления и сопла с ОВТ. Тормозного щитка на гаргроте у Су-35С нет: роль тормоза выполняют рули направления,
отклоняясь в разные стороны.

## Решение
1. **Модель.** `tools/models/fmodel.py`:
   - `MeshBuilder.joint(name, channel, pivot, axis)` регистрирует шарнир, `loft(..., joint=)` привязывает к нему
     оболочку.
   - `lifting_surface()` строит несущую поверхность с вырезанными рулями. Неподвижная часть лофтится сегментами
     по размаху между границами рулей, по оставшимся диапазонам хорды (`chord_slice`). Каждый руль — отдельная
     замкнутая оболочка, поэтому при отклонении в щели видны торцы, а не дыры. Грани по линии реза
     затеняются плоско (`flat_edges`), чтобы не портить гладкие нормали обшивки.
   - Правая половина моделируется, левая получается зеркалом. Для левой копии ось берётся как
     `−mirror(axis)`, тогда **одинаковый угол даёт зеркально-симметричное движение**.
2. **Каналы** (`CH_*` в `fmodel.py` = `gfx::MeshChannel`). Положительный угол означает симметричное движение:

   | Канал | + означает |
   |---|---|
   | 1 стабилизатор | задняя кромка вниз |
   | 2 флаперон | задняя кромка вниз |
   | 3 носок крыла | передняя кромка вниз |
   | 4 руль направления | задняя кромка наружу |
   | 5 сопло | срез вниз (в своей плоскости, наклонённой на 32° наружу от вертикали, как у АЛ-41Ф1С) |

3. **Формат FSM4** ([formats/fsm4.md](../formats/fsm4.md)): один буфер вершин и индексов плюс таблица частей
   (диапазон индексов, канал, сторона, ось вращения и точка на ней). Неподвижный планер — часть 0.
4. **Отрисовка** (`gfx::Mesh::draw(pos, rot, pose)`): часть с нулевым углом рисуется матрицей самолёта, у
   остальных своя матрица: `rot·R(axis, θ)` и перенос `pos + rot·(pivot − R·pivot)`. Всё относительно камеры
   ([0013](0013-camera-relative-rendering.md)). Сейчас 11 вызовов отрисовки вместо одного.
   `Mesh::partTransform` даёт мировую систему части, к ней крепится пламя сопла.
5. **Аниматор** `game::ControlSurfaces` (платформенно-нейтральный, детерминированный). Цели берутся из ввода и
   состояния:
   - стабилизаторы: тангаж ±18° + дифференциал по крену ±8°;
   - флапероны: крен ±20° + выпуск на малой скорости до 15°;
   - носки: по углу атаки до 25° (+10° на малой скорости);
   - рули: рыскание ±25°, тормоз — оба наружу на 30°;
   - сопла: тангаж и крен ±15°, «вес» ОВТ растёт при снижении скорости и равен 1 в ПСМ.

   Приводы ограничены по скорости: 150°/с для рулей, 80°/с для сопел.
6. **Превью.** `build.py` рендерит `build/previews/su35s_posed_*.png` с отклонёнными частями, чтобы проверять оси и
   шарниры. В «Ангаре» части крутятся по демо-циклу (□ — вкл/выкл).

## Рассмотренные альтернативы
- **Отдельные файлы мешей на каждый руль** — больше файлов и загрузок, а атлас всё равно общий.
- **Скелет с весами вершин (скиннинг на GE)** — GE умеет до 8 матриц на вершину, но рулям не нужна гибкая
  деформация, только жёсткий поворот. Отдельные вызовы проще и дешевле.
- **Вырезать рули из готового крыла `bisect` в Blender** — разрез оставляет незамкнутую оболочку и
  неплоские дыры; закрывать их потом сложнее, чем сразу строить из сечений.

## Последствия
- Треугольников стало 6872 (было 6056): торцы и грани разрезов. Вершин 5986.
- Добавить подвижную часть = `joint()` + `lifting_surface(movers=...)` или `loft(joint=)` в описании модели.
- Шасси, фонарь, ракеты на пилонах — тем же механизмом, когда понадобятся.
- Раскрытие створок сопла (диаметр на форсаже) аффинной матрицей не сделать, нужна морф-анимация (открытый вопрос).
- Точки крепления эффектов (срез сопла, законцовки, наплывы) пока заданы константами в
  `fx::kSu35SPoints`; при втором самолёте вынести в файл модели.
