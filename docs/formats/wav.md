# WAV — звук (подмножество RIFF/WAVE)

Пишут: `tools/audio/sfx.py`, `tools/audio/voice.py`. Читает: `audio::parseWav` (`src/audio/wav.cpp`).
Решение — [ADR 0024](../decisions/0024-sound.md). Стандартный формат, а не свой: файлы открываются любым
плеером и редактором, а заголовок разбирается в 40 строк.

## Что принимает игра

| Поле | Требование |
|---|---|
| Контейнер | `RIFF` … `WAVE`, little-endian |
| Чанк `fmt ` | формат `1` (PCM), **1 канал**, **16 бит**, частота 8 000…48 000 Гц (пишем 22 050) |
| Чанк `data` | после `fmt `; **смещение данных чётное** — микшер читает `int16` прямо из блоба файла |
| Прочие чанки | (`LIST`, `fact`…) пропускаются; длина чанка выравнивается до чётной |

Всё остальное (стерео, 8/24 бит, float, ADPCM) — ошибка загрузки, игра показывает путь файла.
Сэмплы не копируются: `audio::Sound` указывает внутрь `core::Blob`, который живёт всю сессию.

## Почему 22 050 Гц моно
Выход PSP — 44 100 Гц, микшер ресемплирует (шаг 0,5 при питче 1). Половинная частота вдвое экономит память
(сейчас ~1 МБ на 15 файлов), а выше 11 кГц в шуме двигателя и голосе через СПУ (300–3400 Гц) почти ничего нет.
Стерео не нужно: панорамой управляет микшер.

## Пример: заголовок, который пишет Python `wave`
`RIFF` <размер> `WAVE` · `fmt ` 16: `01 00` `01 00` `22 56 00 00` (22050) `44 AC 00 00` `02 00` `10 00` ·
`data` <байты> <сэмплы>. Данные начинаются со смещения 44.
