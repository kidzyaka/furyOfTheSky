# PROFILE — профиль игрока (Fury Profile, версия 1)

Пишет: `meta::serialize` (`src/meta/profile.cpp`). Читает: `meta::deserialize`. Файл — `profile.dat` рядом с
`EBOOT.PBP` (запись и чтение с карты памяти — `platform/psp_save`, через временный файл и переименование).
Решение — [ADR 0037](../decisions/0037-campaign-progression-profile.md). Порядок байт — little-endian (как у PSP).
Структуры в память **не копируются**: каждое поле пишется и читается отдельно
([gotchas №18](../psp/gotchas.md#18-детерминизм-не-сравнивать-и-не-пересылать-структуры-через-memcmpmemcpy),
размеры `int`/`uint32_t` на PSP — [№17](../psp/gotchas.md#17-uint32_t-на-psp--это-long-unsigned-int)).

Размер версии 1 — **272 байта** (8 заголовок + 260 данные + 4 CRC). Буфер под файл — `kProfileSaveBytes` = 1024,
запас на рост есть.

## Раскладка

| Смещение | Размер | Тип | Поле |
|---|---|---|---|
| 0 | 4 | char[4] | magic `FPRF` |
| 4 | 2 | u16 | `version` = 1 |
| 6 | 2 | u16 | `payloadSize` = 260 |
| 8 | 260 | — | данные (таблица ниже) |
| 268 | 4 | u32 | CRC-32 байтов `0…267` (magic, заголовок, данные) |

### Медали

Байт на миссию: бит 0 — пройдена на Easy, бит 1 — на Normal, бит 2 — на Hard; старшие биты 0. Нуль — не пройдена.
Ёмкость 8 × 8 (`kMaxLocations` × `kMaxMissions`) зафиксирована форматом: каталог может расти до неё без смены
версии. **Порядок локаций и миссий в каталоге — часть формата**: перестановка сдвинет чужие медали. Сейчас:
0 `north_sea`, 1 `volcanic_isles`, 2 `red_canyons`, 3 `glacier_range`; в каждой миссии 0…3 по порядку кодов.
Индексы `VehicleId` — тоже часть формата (только дописывать в конец).

### CRC

CRC-32 IEEE 802.3, как `crc32()` из zlib: многочлен `0xEDB88320` (отражённый), начальное значение
`0xFFFFFFFF`, итог инвертируется. Проверочное значение для строки `123456789` — `0xCBF43926`. Считается по
байтам `0…267` и пишется little-endian в `268…271`.

## Правила чтения

`deserialize` проверяет по порядку и при любой неудаче возвращает `false`, **не трогая профиль**:
1. размер буфера ≥ 12 байт, magic `FPRF`;
2. `version` равна 1 (другая — старая или новая — отвергается);
3. `payloadSize` равен 260, размер буфера ≥ 272 (лишние байты в конце — например, добивка файла до 1024 —
   игнорируются);
4. CRC;
5. никнейм завершён нулём (последний из 24 байт равен 0).

Разбор идёт во временный `Profile`, в целевой он копируется только после всех проверок. Хорошая CRC доказывает, что
байты не повреждены, но не то, что значения осмысленны (ручная правка, ошибка старой сборки), поэтому после неё:
- `avatar` закрытой (по текущим условиям, `meta::emblemUnlocked`) или несуществующей эмблемы, `lastLocation` ≥ числа локаций, `lastVehicle` ≥ числа машин — сбрасываются в 0 / 0 / Су-35С;
- `balance` < 0 → 0, > 999 999 999 → 999 999 999; громкости > 10 → 10;
- `livery` вне списка ливрей машины → 0; `loadout` обрезается до 5 бит; медали — до 3 бит;
- пустой никнейм → `PILOT`;
- Су-35С всегда `owned` (стартовая машина не теряется).

Запись: никнейм пишется до первого NUL и добивается нулями — мусор после NUL в файл не попадает; результат
побайтно одинаков при одинаковом профиле.

## Как менять формат
- Любое изменение раскладки или смысла полей — новая `version`; читатель версии N принимает только N.
- Совместимое развитие (новое поле): версия N+1, в `deserialize` — ветка, которая читает версию N и достраивает
  значения по умолчанию. Старые версии из этого файла не удаляются, а переезжают в историю ниже.
- Резервные байты (в профиле и в записи машины) нужны, чтобы добавить флаг без смены размера, но и это — новая версия.

## Где проверено
- Хост (macOS, clang): `tests/meta_test.cpp` — круговой обход «поле за полем», смещения из этой таблицы
  (независимая копия в тесте), CRC против эталонной реализации, отказ при испорченном CRC, усечении, чужом magic,
  версии 0 и 2, неверном `payloadSize`, незавершённом никнейме.
- CRC сверен с `zlib.crc32` из Python на настоящем дампе профиля (272 байта) — совпал.
- Синтаксис и предупреждения `-Wall -Wextra` — psp-g++ 15.2.0 (`-fsyntax-only`).
- Чтение и запись на карту памяти PSP — **не проверено** (`platform/psp_save` ещё не готов).
