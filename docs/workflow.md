# Рабочий процесс

## Установка (macOS, Apple Silicon)

```bash
tools/install_toolchain.sh
```

Скрипт идемпотентный, можно запускать повторно:
1. Ставит зависимости Homebrew, **включая `libmpc`**: без неё `cc1` падает с
   `Library not loaded: /opt/homebrew/opt/libmpc/lib/libmpc.3.dylib`.
2. Скачивает `pspdev-macos-latest-arm64.tar.gz` (~147 МБ) с докачкой (`curl -C -`) и проверяет архив `gzip -t`.
3. Распаковывает в `~/pspdev`, дописывает `PSPDEV` и `PATH` в `~/.zshrc`.
4. Собирает игру.

Проверка: `psp-gcc --version` (на 2026-10-13 это GCC 15.2.0).

Шелл, который не читает `~/.zshrc` (агенты, скрипты), должен сам экспортировать `PSPDEV=~/pspdev`. Иначе
`cmake --build build/psp` при пересборке конфигурации падает: `The environment variable PSPDEV needs to be defined`,
`CMAKE_C_COMPILER not set`. Кэш каталога при этом не портится — повторить с переменной (2026-10-15).

## Сборка

```bash
psp-cmake -B build/psp          # конфигурация (один раз)
cmake --build build/psp         # сборка
```

Результат — готовая папка для карты памяти `build/psp/FuryOfTheSky/`:
```
EBOOT.PBP
assets/models/*.fsm, *.ftx
assets/textures/*.ftx
assets/sfx/*.wav
```
`create_pbp_file(... OUTPUT_DIR ...)` кладёт EBOOT прямо туда, пост-шаг копирует всю папку `assets`.

## Тесты симуляции на Mac

```bash
cmake -B build/host && cmake --build build/host && ctest --test-dir build/host
```
Обычный (не PSP) CMake собирает только платформенно-нейтральный код (`src/game`, `src/fx`, `src/audio`, `src/math`, `src/meta`) и `tests/`:
- `flight_model` — 22 проверки модели полёта (ADR 0014, 0038): крейсер, форсаж и 1 Мах, горб волнового кризиса, тормоз,
  набор высоты, перегрузка в вираже, крен, направления управления, сваливание, падение в море, побитовый
  детерминизм, предел α, «кобра», «кульбит», порог ПСМ по скорости, ОВТ на малой скорости, камера в «кобре»,
  камера сзади; подвеска (ADR 0038): полная загрузка `setStores(1, 1)` — эталон бит-в-бит, чистый самолёт разгоняется,
  держит скорость и меньше теряет энергию в вираже (печатает числа), нелепые коэффициенты зажаты; тряска камеры
  выключена — рокот, толчки, пушка и расширение угла зрения не двигают камеру;
- `effects` — 5 проверок эффектов и ловушек (ADR 0020, 0022): нет конденсата на малой скорости при большом α,
  есть в вираже; окно трансзвукового облака и движение скачка; событие 1 Маха одно; залп ловушек в обе стороны
  и в стороне от планера;
- `audio` — звук (ADR 0024): разбор WAV, арифметика микшера (уровни, панорама, питч, разовые звуки, стоп,
  пауза, пригибание под голос, лимитер), правила информатора (тишина в крейсере, задержка 0,25 с, повтор,
  приоритет, «высота опасная» перебивает, молчание после падения, «предельный угол атаки» на живой модели
  полёта), звуки двигателя (раскрутка, форсаж, обдув со скоростью, тряска, тишина после падения), мастер-громкости
  (ADR 0038): шаг 8 = единица, каждая группа слушается своего мастера, пауза глушит мир, но не меню, мастер 0 не
  замораживает разовые звуки, голос на 0 не пригибает двигатель;
- `combat` — оружие, РЛС, бот (ADR 0026–0029, 0033, 0034, 0038), 22 проверки: Р-73 и Р-77 (догон, лоб, вне оси,
  дальности, потеря энергии на манёвре, ловушки), яма РЛС и память, упреждение пушки, учебные режимы и EVADE, бот
  смертен и отстреливается, дуэли уровней, СПО, зона пуска, порядок пусков и перезарядка, полный бой как в
  smoke-тесте, детерминизм; **загрузка вылета**: пилоны вне маски пусты и не заряжаются, у типа без пилонов нет
  резерва, SELECT не выбирает отсутствующий тип, чистый самолёт не стреляет ракетами; **масса и сопротивление**:
  полная загрузка ровно 1,0, ушедшие ракеты облегчают, перезарядка возвращает ровно к 1,0; **конец задания**
  (`game::Objective`): победа через 4 с, поражение через 3 с, кто раньше, тот и остаётся, без задания полёт сам не
  кончается;
- `meta` — каталог, профиль и сохранение (ADR 0037): 16 заданий (коды, длины строк, вариант самолёта у каждого,
  рост награды и противника), открытие заданий и локаций по порядку, награды ×0,6/1/1,5 и повтор за пятую часть,
  звание и пороги, любимая машина, покупка, обрезка никнейма по границе UTF-8, круговой обход и отказ при
  испорченном CRC/усечении/чужой версии (формат — formats/profile.md), маски подвески и наборы;
- `ge_precision` — модель 24-битного усечения матриц GE: почему рендер относительно камеры (ADR 0013).
Запускать после любой правки физики/камеры.

## Smoke-тест в эмуляторе (обязателен перед отдачей на железо)

```bash
tools/smoke_test.sh
```

Запускает сборку в PPSSPP из внутренней «карты памяти» эмулятора с файлом-флагом `autoshot`. 52 скриншота
(точный список и число — в шапке `tools/smoke_test.sh`, `EXPECTED`):
1. **Тур по меню** (21, `kTour` в `src/scenes/menu/menu_scene.cpp`):
   - главное меню; открытый «ящик» SINGLEPLAYER; курсор на TRAINING;
   - тренировка; карусель кампании и она же после сдвига; локация; 4 страницы брифинга;
   - ангар, магазин, профиль, клавиатура позывного, галерея эмблем, настройки, мультиплеер, лобби;
   - дебрифинг выигранной и проигранной миссии (фиктивные: профиль не меняется).
2. **Вылет по скрипту** (31; кадры архипелага и кораблей — сессия «карта океана», ADR 0040+): крейсер,
   вираж на форсаже с конденсатом, ловушки, «кобра», трансзвуковое облако,
   сверхзвук, Р-73 с захватом, пуск, дымный след, попадание, катапультный пуск Р-77, очередь из пушки, захват
   РЛС HARD-бота на СПО, его ракета, проход над водой, падение.

Скрипт:
- сначала статически проверяет ELF на `*ForKernel`;
- затем ищет в логе эмулятора `Unknown syscall`;
- складывает PNG в `build/smoke/`.

Почему именно так — [psp/emulator.md](psp/emulator.md).

Параметры:
- `SMOKE_BUILD=build/psp-xxx` — другой каталог сборки, вывод в `build/smoke-xxx` (параллельная работа);
- `SMOKE_EXPECTED=N` — сколько скриншотов ждать.

Прогоны сериализуются замком `build/.smoke_lock`: «карта памяти» PPSSPP одна на всех. Скрипт кладёт игру на
неё через `rsync --delete`, поэтому каждый прогон начинается с **чистого профиля** (`profile.dat` нет → берётся
никнейм системы эмулятора, `PPSSPP`).

## Деплой на PSP

1. Вставить Memory Stick, запустить `tools/deploy.sh`.
2. Подключить кабель, на PSP: «Настройки → USB-соединение».
3. Скрипт ждёт карту до 2 минут, проверяет свободное место (с 2026-10-14: карта автора была заполнена ISO на
   100 %, rsync упал на середине — `No space left on device`), делает rsync в `PSP/GAME/FuryOfTheSky`, чистит
   AppleDouble-файлы `._*` (`dot_clean`), извлекает карту.
4. Выйти из USB-режима, запустить «Игра → Memory Stick».

На PSP нужна CFW (ARK-4 / PRO-C / LME на 6.61).
Размер игры на карте — ~7,2 МБ (из них звук ~3,9 МБ, в том числе 30 запасных фраз информатора); старая копия при обновлении перезаписывается.

## Какая сборка запущена

Справа вверху HUD — `<git hash>[+] HH:MM` (`+` = собрано с незакоммиченными правками). Генерируется
`cmake/build_info.cmake` на каждой сборке. Сверять с `git log` перед разбором отзыва с железа.

## Фреймрейт и где теряется время

Справа вверху, под id сборки, — строка `S… L… G… ms`, средние за 0,5 с:
- `S` — симуляция (`scene.update`: модели полёта, цель, РЛС, ракеты, расчёт ЗРП, эффекты, звук);
- `L` — построение списка команд GE (`scene.render`);
- `G` — сколько CPU простоял, дожидаясь, пока GE дорисует кадр.

Бюджет кадра — 16,7 мс:
- `S + L` больше бюджета — упираемся в CPU;
- большое `G` — упираемся в GE (вершины, заливка, прозрачность).

Если кадр не уложился в бюджет, частота падает до 30. Цифры PPSSPP на железо не переносятся: эмулятор рисует GE
мгновенно (`G` ≈ 0), а CPU у него быстрее. Мерить только на PSP-3006, по фото экрана.

## Интерфейс меню

```bash
python3 tools/textures/ui.py       # скин, иконки, шрифты (меню и HUD), плашки тревог HUD → assets/ui/,
                                   # src/ui/ui_atlas.h; превью build/previews/ui_*.png
B=/Applications/Blender.app/Contents/MacOS/Blender
$B -b --factory-startup --python tools/textures/locations.py     # картинки локаций (~2,5 мин на CPU; -- <id...> --draft)
$B -b --factory-startup --python tools/textures/schematics.py    # схемы техники (~1 с)
$B -b --factory-startup --python tools/models/hangar.py          # ангар (~25 с; -- --samples N --no-preview)
$B -b --factory-startup --python tools/models/build.py -- su35s_gear   # шасси
```

- `ui.py` нужен Pillow (FreeType) и шрифт PT Sans из macOS; `src/ui/ui_atlas.h` он перезаписывает —
  после изменения атласа пересобрать игру.
- Картинки `north_sea` и `volcanic_isles` от сборки к сборке отличаются на полтона (шум рендера → другая
  палитра k-means), остальные — побайтно одинаковые.
- Подробности — [assets/ui-art.md](assets/ui-art.md), [assets/hangar.md](assets/hangar.md),
  [ADR 0035](decisions/0035-menus-ui.md).

## Звук

```bash
python3 tools/audio/sfx.py         # двигатель, форсаж, обдув, тряска, ловушки, взрыв, меню → assets/sfx/
python3 tools/audio/fetch_voice.py # реальные записи РИ-65 → tools/audio/voice_src/ (не в git; один раз на новой машине)
python3 tools/audio/voice.py       # фразы информатора: записи → assets/sfx/ri_*.wav (без записи — синтез Milena)
cmake --build build/host && build/host/audio_preview   # из корня репозитория → build/audio_preview.wav
```
`audio_preview` летит по сценарию (крейсер, форсаж, 13g, ловушки, «кобра», пикирование в море) через те же модель
полёта, режиссёр звука, информатор и микшер, что и PSP, печатает, когда звучит какая фраза, и пишет 34 с звука.
Слушать после любой правки звуков или уровней — до заливки на PSP. Сценарий повторяет звуковую часть
`FlightScene::stepSimulation`; меняя одно, меняйте и другое.

## Модели

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
    --python tools/models/build.py -- su35s            # + превью
    ... -- su35s --no-preview                          # только ассеты
    ... -- su35s --loadout                             # + ракеты на точках: su35s_loadout_*.png
    ... -- r73   /   ... -- r77                        # ракеты (атлас 128², TEX в модуле модели)
```

Сборка Су-35С занимает ~3 с. Превью (`build/previews/<модель>_<ливрея>_<вид>.png`)
рендерятся из того же квантованного атласа, что уходит на PSP; `<модель>_posed_*.png` — с отклонёнными рулями и
соплами (проверка шарниров). Лог сборки печатает таблицу частей: канал, сторона, ось, точку на оси. После изменения модели —
пересобрать игру (ассеты копируются в папку для карты памяти при сборке).

### Деплой из другого каталога сборки
`DEPLOY_BUILD=build/psp-ocean tools/deploy.sh` — как `SMOKE_BUILD` у smoke-теста. Нужен, когда параллельные сессии
собирают в своих каталогах (по умолчанию `build/psp`).
